# 로컬 자동화 웹앱 만들기

요청: $ARGUMENTS

CutFlow(유튜브 영상 자동 편집 앱)를 만든 과정을 일반화한 절차다. 단계 순서대로 진행하되, 각 단계의 **완료 기준**을 실제로 확인한 뒤 다음으로 넘어간다. 세부 패턴은 같은 폴더의 참고 문서에 있다.

- [architecture.md](architecture.md): 폴더 구조, 액션 파이프라인, 서버 API, 보안 규칙
- [design.md](design.md): 레퍼런스에서 디자인 토큰 뽑기, 화면 구성 요소
- [ai-layer.md](ai-layer.md): API 키로 여는 AI 기능 (Claude)
- [testing-ci.md](testing-ci.md): 격리된 테스트, 가짜 입력 생성, CI 템플릿

## 0. 요구사항 정리 (먼저 확인)

인수에서 알 수 없는 것만 묻는다. 한 번에 묶어서 묻는다.

- 자동화할 **작업 목록**: 각각 독립 기능(액션)이 된다. 예: 무음 제거, 쇼츠 추출, 메타데이터
- **디자인 레퍼런스** URL (없으면 기본값: 네이비 사이드바 + 블루 그라디언트)
- **AI로 할 일**: API 키가 있을 때만 여는 기능
- **실행 환경**: 대개 Windows 로컬. 셸, 경로의 공백·한글 여부 확인

## 1. 레퍼런스 디자인 분석

브라우저로 레퍼런스를 열어 스크린샷을 찍고, [design.md](design.md)의 표에 따라 색·모서리·그림자·타이포·핵심 모티프를 뽑는다. 이미지·로고·문구는 **가져오지 않는다**. 분위기와 구성만 참고한다.

**완료 기준:** `:root` 디자인 토큰 초안과, 레퍼런스에서 가져올 구성요소 목록 3~5개 (예: STEP 표시, 둥근 카드, 수치 배지).

## 2. 환경 점검

`python --version`, `node --version`, 필요한 외부 바이너리(ffmpeg 등)를 확인한다. 외부 바이너리는 **pip 패키지에 포함된 것**을 우선한다 (예: `imageio-ffmpeg`). 사용자가 따로 설치하지 않아도 되게 하기 위해서다.

**완료 기준:** 필요한 패키지 설치, 핵심 바이너리 경로 확인.

## 3. 핵심 로직 (순수 함수 먼저)

외부 도구 호출은 `media.py` 같은 얇은 래퍼 하나에 모으고, 판단 로직(분석·점수·구간 계산)은 **입출력이 단순한 순수 함수**로 따로 둔다. 테스트하기 쉬워진다.

**완료 기준:** 가짜 입력으로 핵심 함수들이 기대한 값을 낸다.

## 4. 액션 파이프라인 + 서버

[architecture.md](architecture.md)의 `Job` 패턴을 따른다.
- 기능마다 `_do_<action>()`을 하나씩 만든다.
- 선행 단계(분석 등)는 자동으로 추가한다.
- 결과는 작업 폴더에 쌓는다.
- 웹 서버용 `start()`(스레드)와 CLI·테스트용 `run_sync()`를 둘 다 둔다.

서버 규칙:
- 결과 폴더만 정적 공개하고, 설정 파일(API 키)은 절대 공개하지 않는다.
- 알 수 없는 액션은 400, 키 없는 AI 액션은 403으로 거절한다.

**완료 기준:** API로 업로드한 뒤 액션 하나만 실행 → `done`. 같은 작업에 다른 액션을 추가 실행해도 `done`.

## 5. 화면 (바닐라 JS SPA)

빌드 단계 없는 `index.html` + `style.css` + `app.js`로 만들고, 해시 라우팅을 쓴다. 필수 화면:

1. **대시보드**: 히어로, 통계, 기능 소개, 최근 작업
2. **새 작업**: 업로드 → 기능 카드
   - 카드마다 스위치(함께 실행)와 `이 기능만 실행` 버튼
   - AI 기능은 잠금 타일로 표시
   - 하단 고정 바에 `선택한 기능 실행`
3. **처리 중**: 진행 링, 단계 목록, 로그 (1초 폴링)
4. **결과**: 수치 카드, **기능 실행 패널**(작업에 기능 추가·재실행), 결과 탭
5. **AI 도구**: 대상 작업을 고르고 AI 기능을 버튼으로 실행 (키가 없으면 인라인 키 입력)
6. **설정 / 작업 기록**

잠긴 AI 버튼을 누르면 **키 입력 모달**이 뜬다. 키는 저장 전에 무료 API로 검증한다.

**완료 기준:** 브라우저에서 화면 이동, 콘솔 오류 0개, 모바일 폭(375px)에서 가로 스크롤 없음, 잠긴 버튼 → 키 모달 동작.

## 6. AI 기능

[ai-layer.md](ai-layer.md)를 따른다. Claude 호출 코드를 쓰기 전에 `claude-api` 스킬이 있으면 **반드시 먼저 읽는다** (모델 ID와 파라미터가 자주 바뀐다). 키가 없으면 규칙 기반으로 대체하거나, 기능을 잠근다.

**완료 기준:**
- 가짜 키로 호출하면 401 → 요청 형식은 정상이라는 뜻
- `ai.call`을 가짜 함수로 바꿔 모든 AI 액션의 파일 저장 확인

## 7. 자동 처리 워크플로우 (CLI)

- **`app/cli.py`**: `process <파일>`, `watch`(inbox → outbox, 처리한 원본은 done/, 실패는 failed/ + 오류 txt), `presets`
- **`workflow.json` 프리셋**: `actions` + 키가 있을 때만 도는 `ai_actions` + `options`
- **감시 규칙**: 복사 중인 파일은 크기가 두 번 연속 같고 쓰기 모드로 열릴 때까지 기다린다.
- **실행 파일**: Windows용 `.bat`(CRLF)과 시작프로그램 등록 스크립트(`.ps1`, UTF-8 BOM). 등록 스크립트는 **사용자가 직접 실행**하게 안내한다.

**완료 기준:** `watch --once`로 샘플 파일 처리 → outbox에 결과와 요약 파일이 생긴다.

## 8. 테스트 · CI · 저장소

[testing-ci.md](testing-ci.md)를 따른다.
- **테스트 격리**: 작업 폴더를 환경변수로 임시 폴더로 바꾸고 API 키를 비운다. 테스트 입력은 코드로 생성한다.
- **저장소 파일**: `.gitignore`(`.env`, 작업 폴더, inbox/outbox), `.gitattributes`(bat/ps1 CRLF), `.env.example`
- **문서**: `CLAUDE.md`(`@agent.md` 임포트 + Claude 전용 메모), `agent.md`(구조·규칙·검증)
- **CI**: GitHub Actions에서 Ubuntu + Windows 매트릭스로 실행한다.

push하기 전에 두 가지를 확인한다.
- staged 파일에서 비밀 값 스캔 (예: `git grep --cached -nIE "sk-ant-[A-Za-z0-9_-]{20,}"`)
- 무거운 산출물이 올라가지 않는지

**완료 기준:** 로컬 `pytest` 전부 통과, push 후 CI 초록색.

## 9. 실제 입력으로 끝까지 검증

단위 테스트만으로 끝내지 않는다. 사실적인 샘플로 전체 흐름을 한 번 돌려 결과 파일을 직접 연다.
- **음성 샘플**: Windows는 `System.Speech`로 한국어 TTS를 만들 수 있다.
- **확인 대상**: 결과 이미지 프레임, 자막 렌더링

테스트용으로 만든 작업은 사용자 작업 폴더에서 **삭제**한다. 가짜 AI 결과가 남으면 사용자가 헷갈린다.

- 요금이 나오는 기능
